## Project Context

This incident report documents a simulated cyberattack conducted inside a home Security
Operations Center (SOC) lab built to detect attack techniques used by Russian state-sponsored
groups against Ukrainian infrastructure, as documented by CERT-UA — Ukraine's national
Computer Emergency Response Team.

The lab was built from scratch using virtualization software. No real systems, real credentials,
or real networks were involved. Every component was self-configured. The attack simulation and
detection process mirrors the workflow of a real SOC analyst responding to an active threat.

---

## Lab Architecture

Before the attack simulation, I built a complete Windows enterprise environment:

**Domain Controller — Windows Server 2019**
Installed and configured Active Directory Domain Services through the Windows GUI. Created the
domain MYDOMAIN.COM. Built five organizational units (HR, IT, Finance, Sales, Management).
Used a PowerShell script to bulk-import 1,056 user accounts from a CSV file into the correct
OUs. Configured group policies including password complexity and account lockout. DC runs at
IP 172.16.0.1.

**Target Workstation — Windows 10 Enterprise**
Configured and joined to MYDOMAIN.COM. Runs at IP 172.16.0.100, identified as
CLIENT1.mydomain.com. This is the machine the simulated attacker compromised and
where the credential dump was performed.

**SIEM — Wazuh 4.14.5**
Deployed Wazuh on a dedicated Ubuntu Linux virtual machine at IP 172.16.0.101. Wazuh is
an open-source SIEM used by security operations centers worldwide. It collects event logs from
connected machines, runs detection rules against those logs, and generates alerts when
suspicious activity is identified.

**Wazuh Agents + Process Auditing**
Installed the Wazuh agent on both machines. Each agent continuously forwards Windows event
logs to the Wazuh server. Enabled Windows process creation auditing using `auditpol`, which
instructs Windows to log every process that starts as Windows Security Event ID 4688.

## Threat Intelligence Foundation

This lab was built around real threat intelligence published by CERT-UA.

**APT28 — UAC-0028**
APT28 is a Russian military intelligence unit (GRU), also known as Fancy Bear and Forest
Blizzard. CERT-UA tracks them as UAC-0028 and has published dozens of advisories documenting
their operations against Ukrainian targets since at least 2021, accelerating after the
full-scale invasion in February 2022.

**What APT28 targeted in Ukraine**
Ukrainian government ministries, energy infrastructure, military communications, scientific
institutions, and diplomatic facilities — the systems that keep a country functioning during
an active war.

**How credential dumping fits their operations**
APT28 typically begins with phishing — one compromised machine inside a target network.
Credential dumping then lets them spread: stolen NTLM hashes authenticate to other machines
across the domain without needing further phishing. A December 2023 CERT-UA advisory
documented APT28 moving from initial phishing to threatening an entire domain controller
within one hour. Credential dumping is what makes that speed possible.

## Executive Summary

On June 17, 2026, a credential dumping attack was simulated on workstation CLIENT1.mydomain.com
in the MYDOMAIN Active Directory environment. The domain account a-jbabushka executed Mimikatz
through Command Prompt with administrator privileges. Mimikatz accessed LSASS process memory
and extracted NTLM password hashes for domain accounts. Windows Security Auditing captured the
process creation as Event ID 4688 and the Wazuh agent forwarded it to the SIEM, where Rule
67027 triggered. This technique matches documented methods used by APT28 (CERT-UA: UAC-0028)
against Ukrainian government organizations.

## What Happened

### The Target — LSASS

LSASS (Local Security Authority Subsystem Service) handles Windows authentication. Every time
a user logs in, their credentials are stored in LSASS memory — NTLM hashes, Kerberos tickets,
and in some configurations plaintext passwords — for every account that has touched the machine.

An attacker with administrator access who can read LSASS memory gets credentials for every
domain account on that workstation, including accounts with access to servers, databases, and
domain controllers across the entire network.

### The Tool — Mimikatz

Mimikatz is a legitimate security research tool used daily by penetration testers to test
credential storage vulnerabilities. I used it with administrator privileges, targeting LSASS
memory directly.

**`privilege::debug`**
Requests debug privilege — an exception to Windows memory access restrictions originally
designed for software developers. Attackers abuse it to read protected process memory.
Output confirmed: `Privilege '20' OK`.

**`sekurlsa::logonpasswords`**
Reads LSASS memory and extracts all credential material. Output returned username
`a-jbabushka`, NTLM hash `64f12cddaa88057e06a81b54e73b949b`, and plaintext password
`Password1`. With the NTLM hash, an attacker can authenticate to any system that account
can access without knowing the plaintext password — Pass-the-Hash.

### The Detection

Process creation auditing logged the start of `mimikatz.exe` as Event ID 4688, capturing:

```
Full path:      C:\Tools\mimikatz\x64\mimikatz.exe
Parent process: C:\Windows\System32\cmd.exe
Account:        a-jbabushka (MYDOMAIN)
```

The Wazuh agent forwarded this event to the SIEM within seconds. Rule 67027 matched and the
alert appeared in the Threat Hunting dashboard. Detection occurred at the process creation
stage — before credential exfiltration was complete.

## Recommendations

**1. Enable Windows Credential Guard**
Credential Guard isolates LSASS in a virtualized secure environment using Windows Hypervisor.
No process can read LSASS memory directly — not even with debug privileges. If active during
this simulation, `sekurlsa::logonpasswords` would have returned empty results. This is the
single most effective mitigation against T1003.001.

**2. Remove local administrator rights from standard domain users**
Mimikatz requires administrator privileges to access LSASS. Without local admin rights,
`privilege::debug` fails immediately and the attack cannot proceed. The account `a-jbabushka`
should not hold local admin rights on CLIENT1. Enforcing least privilege eliminates the
conditions this attack requires before any tool is run.

**3. Implement dedicated detection rules for credential dumping tools**
Wazuh Rule 67027 at level 3 is a generic process creation alert — it fires for every process
on the machine. A production SOC needs a dedicated rule at level 10 or higher, specifically
watching for known dumping tool names and paths (`mimikatz.exe`, `procdump.exe`,
`lsass.dmp`), generating an immediate page to an on-call analyst.

**4. Enable MFA across the domain**
The NTLM hash for `a-jbabushka` is now usable for Pass-the-Hash authentication against any
accessible system in MYDOMAIN. With MFA enforced, a valid hash alone is insufficient to
authenticate. This reduces the operational value of a credential dump to near zero.

**5. Monitor for lateral movement following credential alerts**
Credential dumping is the bridge to the next attack stage. After obtaining hashes from CLIENT1,
the attacker authenticates to other machines: domain controllers, file servers, email systems.
Watch for Event ID 4624 Type 3 (network logon) from unexpected source IPs immediately
following any credential access alert. That combination is the signature of active lateral
movement.

## Why This Technique Was Used Against Ukraine

APT28 is a Russian GRU military intelligence unit that has conducted cyberattacks against
Ukraine since at least 2021, massively escalating after the full-scale invasion in February
2022. CERT-UA tracks them as UAC-0028 and has published dozens of advisories documenting
their operations.

Their standard approach: phishing gets them onto one machine. Credential dumping is what
spreads that access across the entire organization. Stolen NTLM hashes authenticate to other
machines without further phishing. A December 2023 CERT-UA advisory documented APT28 moving
from initial phishing to threatening an entire domain controller within one hour. Credential
dumping is what makes that speed possible.

Their Ukrainian targets were the systems that keep a country functioning during an active war:
government ministries, energy infrastructure, military communications, scientific institutions,
diplomatic facilities. When credentials are stolen from one government workstation, potentially
every server, database, and communication system that account can reach is exposed.

I built this lab because I am from Ukraine. The attacks documented by CERT-UA were not
abstract to me — they targeted the infrastructure of the country I left. The technique
simulated here is documented in real CERT-UA advisories as something done to real Ukrainian
organizations by a real Russian military unit. Building a lab to detect it was my way of
understanding the attack well enough to respond to it.

## What I Learned

Building this lab taught me things that courses and study notes cannot. Troubleshooting why
Wazuh agents were not connecting, fixing firewall rules that were blocking log forwarding,
debugging network configuration across four virtual machines — those problems taught me how
these systems actually fail in practice. The documentation describes how they should work.
The lab showed me how to fix them when they do not.

Running Mimikatz and then finding the alert in Wazuh connected two things that felt separate
when I was studying: the attacker's perspective and the defender's. When I ran
`sekurlsa::logonpasswords` and saw real domain credentials appear in the output, I understood
in a concrete way why LSASS is the highest-value target on a compromised Windows machine.
When I found the Event ID 4688 alert in Wazuh and read through each field, I understood what
a SOC analyst needs to see to respond effectively.

Writing the incident report was a different discipline — translating what happened in the lab
into a document that communicates the technical facts, timeline, indicators, and
recommendations to someone who was not there. That is the skill that makes a SOC analyst
useful to an organization rather than just technically competent.

The next step I would build is detection of lateral movement using the stolen credentials.
Running a Pass-the-Hash attack from a second machine using the `a-jbabushka` NTLM hash, then
writing a Wazuh rule triggering on Event ID 4624 Type 3 network logon events from unexpected
source IPs. That extends detection coverage from the initial credential theft to the lateral
movement stage that follows — the full attack chain APT28 uses against Ukrainian targets.
